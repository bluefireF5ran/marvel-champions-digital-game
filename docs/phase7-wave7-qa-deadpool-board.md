Audit, 2026-10-06, desktop board only (phone not run). Each card was staged the Break Time way (`packages/client/src/store/dev-qa-deadpool-game.ts`:
a real game played forward through the store with `SessionConfig.stack`, no state edits) and driven with pointer input
in `packages/client/e2e/wave7-deadpool-cards.spec.ts`. Outcomes were read back from the engine state and matched to the
card's script tests in `packages/cards/src/wave7/deadpool/`. Nothing in the client or engine was changed.

## Notes

- Selecting an option and pressing Confirm on a sheet that has just opened can lose the press while the cards fade in;
  the spec repeats the cycle and checks the engine's pending choice changed (`answer()` in the spec). A player taps
  again, so this is cosmetic, but a sheet that ignores input for its first moments is worth a look
  (`packages/client/src/scenes/choice.ts`).
- Not audited (no unusual prompt beyond the generic sheets already covered): Break the Fourth Wall's deck search
  (44001b) and the card-face picker for Bob's and Negasonic's simple choices.
- Fixtures: `dev-qa-deadpool-game.ts` takes `blackout | ticTacToe | gitGud | plotConvenience | rockPaperScissors |
  armedToTheTeeth | merc`; `dev-qa-deadpool-game.test.ts` proves each reaches its state. The first stacked card is a
  44017 so the hand-limit discard (first card, answered with its minimum) takes the filler, not the card under test.
